# 实际使用后的复盘

每次能够核对结果的采集、预检或归档完成后，记录在跑的技能版本、目标客户端版本和本次核对结果。对照预期范围核对计数、错误码及缺件，优先区分源材料、权限、客户端灰度、格式兼容和程序缺陷。仅用公开资料或合成用例验证时，登记相应证据范围。

如同一授权环境已有 `wechat-evidence-expert` 1.3.0，使用其 `scripts/main.py` 登记。本次预检的 JSON stdout 或归档 `manifest.json` 保留在私有目录；复盘状态目录位于两个技能目录之外。

```bash
python3 "$EVIDENCE_SCRIPT" --state-dir "$STATE" review-use --receipt "$RECEIPT" --origin actual --skill-version 0.3.0
```

用户核对过具体结果时才用 `--feedback confirmed`，指出实际差异时用 `--feedback corrected`，同时以 `--run-id` 传回初次登记输出的运行编号。暂未收到回复时保留 `pending`。合成验证使用 `--origin synthetic`。没有可用回执时，可单列本人观察到的阶段、实际状态、退出码和本机版本，附获授权的原始回执定位。工具未安装时，将这些字段写入本次授权目录或当前记录，业务产物仍按原验收要求核对。

待处理的问题应能写成“哪些输入和命令下，预期得到什么，实际得到什么”。首修会造成丢失、错归或不可复核的问题。使用脱敏或合成夹具复现，固定样本哈希、命令、环境和预期，再做最小改动。用同一夹具及邻近边界复测，记录通过结果、版本、适用范围和回退提交。如主张提效，在同输入、机器和参数下记录修复前后耗时，并核对产物一致性。

复盘只用必要计数和状态，真实聊天、账号、路径、密钥或附件内容留在授权处理环境。变更在获得可复核结果后写入同一技能。更新、部署、个人技能加载和实际试点分别登记。
