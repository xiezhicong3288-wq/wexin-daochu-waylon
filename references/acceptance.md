# 验收要求

区分代码生成、个人技能安装、本机组件部署、入口调用、合成技术验证、指定真实材料验证。工程环境成功不代表 Windows 成功，手动读回不证明自动路由。

## 必测边界

1. 固定源码逐文件相符；缺失/篡改拒绝；准备器不执行压缩包内容。
2. 静态原件/冻结输入前后哈希一致，输入输出不重叠，新输出不覆盖；运行、数据、技能目录分开。
3. 明确账号、会话、时间；跨已知账号拒绝；同名不同ID、群内重名、改名不误并。
4. 每条顶层消息有索引或异常；嵌套独立统计，重复保留并标记，未知类型不静默丢失。
5. 文件哈希＋JSON路径/行号可定位；原始ID保持精度，不把程序序号当原生消息号。
6. 原时间、时区、展示分开；回退/未知/不支持单位明确；明确时区下展示值矛盾须提示，规则缺失不可冒充检查通过；不伪造原始发言时间。
7. 附件路径逃逸、绝对路径、URL、UNC、符号链接、Windows reparse/junction拒绝；可用文件存在且哈希可核。
8. HTML转义、CSV公式防护、正文不执行；非法JSON、重复键、非有限数和异常回执不泄露正文。
9. 适配器不联网或启未授权子进程，不自动重连/更新/提权；密钥不落盘或输出。
10. 输出冲突、取消、损坏库、异常有明确状态；不删除旧产物，恢复先对账。

## 0.2.0 深化检查

- 固定事前文件清单后移除分库，必须在完整成功前拒绝；未提供事前清单时只称当前输入范围核对。
- 独立 SQL 读取所有提供库中所选会话表，用物理 rowid 或声明主键定位，保留相同内容和重复编号的出现次数；不要用被测取数函数产生预期值。
- 对实际保存的 JSON/JSONL/HTML 数据逐条核对；最终整理再对照固定导出哈希、原导出副本、源位置、正文/编号/时间/发送者及嵌入父子关系。显示名、时间依据、时区与展示一致性标签也须来自固定导出和明确转换规则。相同数量但丢一条加一条、改正文、解释标签或来源不能通过。
- 解码与构建消息失败必须保留阶段、物理源行和安全错误类别；未确认落盘的源行逐条列为拒绝，不能以笼统运行失败代替具体故障位置。
- 保存原始数据库及关联文件的字节清单、复制窗口、变化检查；工作副本与原件分离。按 SQLite 规则验证 WAL 校验链及可信提交边界，健康未提交尾帧不计提交；坏头、伪造提交标记、部分帧截断必须拒绝。未知校验域和旧世代盐值尾部保守停止，不绕过。
- 已知整页/整事务缺失依赖事前清单；结构正常或自洽的短文件不能自行证明历史完整。文件保存、单库结构/事务状态、多库共同时间点分别报告。
- 普通正文 TEXT、UTF-8 BLOB、ZSTD 及纯空白保持一致；发送者指示冲突保留双方，不选定身份；引用缺时间不回填父时间，重复编号匹配不擅自采用第一条。
- 少量输入顺序、显示名、重复执行变形保持语义归属和内容等价。运行时间、路径与随机 WAL 盐值等非语义差异单列。

将 ISO/IEC 27037:2012、27041:2015 的已读公开摘要用于材料处理与适用性验证设计，将 NIST CFTT 方法概览用于需求/断言/用例/结果映射，按 SQLite 官方 WAL 文件格式核对头部、校验及读取边界。上述不是全文条款审计或认证。来源与读取边界见深化方案及当前验证记录。

## 真实试点

Windows 部署需先在该环境运行合成验证。当前 Python 的路径 stat 与句柄 fstat 可能给出不同含义的 ctime：跨 API 对齐文件身份、大小、mtime 与创建时间，句柄前后和路径前后仍各自保留完整变化检查。不能删掉 ctime 检查来掩盖误报。准备器必须核对 ZIP 原始成员名称，不仅核对 Windows 已规范化的名称。测试数据库须显式关闭；符号链接权限不足只标记对应用例未测，不提权，reparse 属性检查继续运行。

在已授权目标电脑及确切微信版本上完成一单聊、一群聊试点。程序对账全范围，抽核不少于30条（不足全查）并覆盖实际存在的类型。未解释的正文、身份、时间差异不能通过。无法恢复的附件可记部分完成，须列数量与原因。

使用合成账号、聊天、数据库作测试，不提交真实资料、密钥、身份映射或敏感日志。独立测试接收原始样本和任务，不泄露预期修复。真实用户反馈与机器测试分别记录。
